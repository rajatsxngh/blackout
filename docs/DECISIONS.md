# Decision log

Every design decision gets one entry (docs/PRD.md §10), newest last. To change a decision, add a new entry that supersedes the old one; don't edit history.

| ID | Date | Decision | Why | Alternatives considered |
|---|---|---|---|---|
| D001 | 2026-11-07 | Official `anthropic` Python SDK behind a thin `LLMClient` interface | One provider; full access to prompt caching, effort, strict tools, structured outputs, batches and usage fields | LiteLLM (can lag behind new parameters) |
| D002 | 2026-11-07 | Solver baseline uses OR-Tools CP-SAT over enumerated truck plans | Exact at this size; deterministic with `num_workers=1` and a deterministic time limit; optimizes dark minutes directly | OR-Tools routing API (needs workarounds for reloads, finite stock and draining tanks; its local search stops on wall-clock limits) |
| D003 | 2026-11-07 | Static replays only; no live or WebSocket mode | Demos use replays, so there's no live API cost or lag | FastAPI + WebSockets |
| D004 | 2026-11-07 | JSONL run logs instead of a tracing service | No extra service to run; the logs already hold everything and drive replay | OpenTelemetry + Langfuse |
| D005 | 2026-11-07 | Viewer built with Vite + React + TypeScript + Canvas 2D | Simplest option for fewer than 50 animated entities | PixiJS |
| D006 | 2026-11-07 | Contestants are woken only by their own observation stream | A wake-up caused by hidden truth would leak information | Triggers computed from ground truth |
| D007 | 2026-11-07 | Every false report carries at least one cue, plus a `confirm_report` action | Careful reading can then win at L2, not just blanket distrust | False reports with no detectable cue |
| D008 | 2026-11-07 | Haiku 5.5 for building and for the complete design; Opus 5.5 coverage decided by priority fill within budget caps | Cost per run is uncertain (could be 2–3× the estimate), and this keeps every research question answerable within $400 | A fixed full matrix on Opus |
| D009 | 2026-11-07 | Python pinned to 3.12 (`>=3.12,<3.13`), managed by uv with a lockfile | Reproducible environments and a single interpreter version to support | Floating Python versions |
| D010 | 2026-11-07 | LF line endings everywhere, enforced by `.gitattributes` | File hashes (scenario manifests, golden files) must match on Windows and Linux | Git's default CRLF conversion on Windows |
| D011 | 2026-11-07 | Pre-commit runs ruff from the project environment (local hooks) | Hooks and CI use the same locked ruff version | A separately pinned `ruff-pre-commit` revision |
| D012 | 2026-11-07 | CI pins `astral-sh/setup-uv` to an exact release (`v10.3.3`) | That action publishes no floating major tag | `@v10`, which doesn't exist |
| D013 | 2026-11-07 | Determinism rules are enforced by tests (`tests/test_guardrails.py`) | Rules in a document get forgotten; a failing test doesn't | Code review only |
| D014 | 2026-11-07 | Truck routing uses a small hand-written Dijkstra that breaks ties by node ID (`sim/routing.py`); NetworkX waits for the M4 dependency graph | Every platform must pick exactly the same path among equally fast ones | NetworkX shortest paths (tie order depends on graph internals) |
| D015 | 2026-11-07 | Tick semantics: events at tick t apply before decisions at t. Each minute: hospitals burn, then trucks drive, load and unload, then statuses update. A delivery lands at the end of its fifth unloading minute, so it covers the next minute's burn | One fixed, documented order makes replays and tests exact | Other orderings (equally valid, but one has to be chosen) |
| D016 | 2026-11-07 | Scenario files are self-contained and versioned (`schema_version: 1`). The schema lives in `blackout.scenarios.schema`; event models live in `blackout.sim.events` | The engine's input contract has a single definition; the M5 generator writes the same format | Defining the schema inside the engine |
| D017 | 2026-11-07 | Already from M1, wake triggers come only from observable signals: fleet status, hospital telemetry, time-to-failure crossings, and a heartbeat 15 ticks after the last decision point. Hidden road events never wake anyone | Builds the M4 rule (D006) in from the start instead of retrofitting it | Truth-based triggers in M1, fixed in M4 |
| D018 | 2026-11-07 | Action fields carry their units (`amount_l`). A vehicle gets one movement action per decision point, and a rejected action doesn't use up its turn | Clear for people and LLMs; mistakes can be corrected within the same turn | Unitless `amount`; counting rejected attempts against the vehicle |
| D019 | 2026-11-07 | A breakdown freezes a truck where it is (mid-road allowed) and a repair resumes what it was doing. A stuck truck waits until it gets a new dispatch or reroute | Simple, predictable, and leaves recovery decisions to the contestant | Automatic rerouting by the engine |
| D020 | 2026-11-07 | Provisional: M1 hospital telemetry shows the true current burn rate | Keeps M1 simple. M4 may smooth or delay it so that T05 (burn spike) rewards reading staff reports | Hiding burn rate from M1 onwards |
| D021 | 2026-11-07 | A run stops early once no events are pending and every hospital has grid power | Nothing can change after that, so further minutes would only add cost | Always running to the horizon |
| D022 | 2026-11-07 | CI enforces an 85% branch-coverage floor. Golden run hashes in `tests/test_demo.py` pin the demo trajectories | Keeps the PRD's coverage target honest and catches unintended physics changes on both OSes | Coverage as a report only; no golden runs |
| D023 | 2026-11-07 | Trucks and crews share a `Vehicle` base and one `VehicleState` enum (`TruckState` renamed). Crews drive the same roads and can get stuck on hidden blocks too | One movement and validation path for every vehicle | Separate crew movement code |
| D024 | 2026-11-07 | Power step: overloaded minutes are counted on the feeds in place at the start of each minute; a substation trips on its 3rd consecutive overloaded minute; its zones move to their backup feeds in that same minute, and the backup's count starts the next minute | Every stage of a cascade gives contestants the same 3-minute window, and the timing is exact and testable | Instant cascades within one minute |
| D025 | 2026-11-07 | Feeds, loads and hospital statuses are re-resolved right after events, shed or restore actions, and repairs | Observations always show the state the next minute will start from | Updating power only once per minute |
| D026 | 2026-11-07 | A failed substation's repair time is hidden until a crew is working on it (only then is `work_left` shown). A tripped substation needs a 10-minute crew reset | Telemetry shows that a substation is down, not how badly; damage estimates arrive with M4's reports | Showing repair times up front |
| D027 | 2026-11-07 | Signals caused by a contestant's own action (such as a zone going dark because it was shed) don't wake it again; delayed consequences (overloads, completed tasks) still do | It already has the action's result, so an extra wake-up would only cost a decision point | Waking on every state change |
| D028 | 2026-11-07 | Shedding a zone that's already shed is rejected (`zone_already_shed`) rather than accepted as a no-op | No silent no-ops: the contestant learns its picture of the grid was wrong | Accepting it silently |
| D029 | 2026-11-07 | Unmet demand is weighted critical 100, essential 10, residential 1 (in `SimConfig`) | The same weights the solver uses for shedding (PRD §8.7), so one scheme runs through the project | Separate metric weights |
| D030 | 2026-11-07 | Scenario schema v2: a hospital gets power from the zone containing its intersection; one outside every zone is off the grid. Zones containing a hospital must be `critical`. v1 files are no longer accepted | The grid becomes part of the world instead of a per-hospital flag | Keeping `grid_powered` alongside zones |
| D031 | 2026-11-07 | The early stop (D021) now also requires every zone to have power and no substation to be overloaded. A second failure during a repair loses the crew's work; a crew sent to a working substation just waits there | Stopping must never hide a pending trip or an outage | Stopping on hospital power alone |
| D032 | 2026-11-07 | Golden run hashes were re-pinned for M2: hello_blackout gained a grid and a crew, and the cascade scenario was added | Intentional physics change (D022) | — |
| D033 | 2026-11-07 | Run logs are deterministic text: canonical JSON lines (sorted keys) in gzip with a fixed header (mtime 0, no file name). Time, platform, Python version and git commit go in `summary.json` | The same run gives a byte-identical log on any machine, which makes logs comparable and diffable | Timestamps and machine details in the log header |
| D034 | 2026-11-07 | The log header embeds the full scenario together with its digest | A log can be replayed and scored on its own, even if the scenario file moves or changes; the digest catches a mismatch | Referring to the scenario file by path |
| D035 | 2026-11-07 | The scorer gets outcome metrics by replaying the log with the engine, after every state hash has been verified, and counts process metrics directly from the decision records. Both are cross-checked against the end record | The engine is the referee; I5 is about never trusting a contestant's numbers, and a second physics implementation would just be a second source of bugs | Re-implementing the physics accounting inside the scorer |
| D036 | 2026-11-07 | Replay re-issues every logged action, rejected ones included. It checks decision ticks, observation digests and action outcomes as well as state hashes, and stops at the first difference | Rejected actions count toward the metrics, and the earliest difference is the most useful error | Replaying accepted actions only and comparing hashes at the end |
| D037 | 2026-11-07 | `blackout run` writes a log by default (to `runs/adhoc`; `--out`, `--no-log`), and `blackout replay` always verifies, so there's no `--verify` flag | Every run should leave a record, and a replay that doesn't check anything has no purpose | Logging opt-in; a separate verify flag |
| D038 | 2026-11-07 | Scenario schema v3: radio reports are scenario events (`kind: "report"`) with channel, source class, source, structured `facts`, optional `text` and hidden `truth`; scenarios gain a messiness `level`. Contestants get the facts at L0 and only the text at L1+. v2 files and logs that embed them are refused with a clear message | Reports sit in the same deterministic event heap as everything else, and one field decides what a contestant may read | A separate report file; always showing facts |
| D039 | 2026-11-07 | Wake triggers come from comparing consecutive observations of each role (`blackout.info.wake`), measured from the observation after the role's own actions. The engine's truth signals stay, but wake contestants only with `wake_on_truth=True` (the reference, M7). Golden run hashes did **not** change: with no delay and the full view both give the same decision points on the hand-made runs (tested) | A role can only be woken by what it can see, by construction (I6), including under delays and role filters | Filtering the engine's truth signals by role |
| D040 | 2026-11-07 | New `road_status` trigger whenever a block enters a role's telemetry, even alongside `vehicle_stuck` | Transport must hear about a block a Power crew found; one rule for every role | Announcing blocks only through the stuck vehicle |
| D041 | 2026-11-07 | Role scopes: Power sees substations, zones and crews; Hospitals sees hospitals; Fuel sees depots and trucks (read-only); Transport sees trucks and roads; `all` sees everything. Reports go by channel (crew radio, hospital staff, depot staff, police radio; public to everyone). `BlackoutEnv(roles=...)` wakes only the roles with triggers, each with its own heartbeat; `run_episode` drives one role | The union of the team's views equals the single agent's view (PRD 8.9), and routing never looks at content | Waking every role at every decision point |
| D042 | 2026-11-07 | The telemetry delay makes whole hospital and depot readings D ticks old, each with an `as_of` tick; fleet, grid and road telemetry stay real-time. Delay, confirm delay (8) and confirm limit (4) live in `SimConfig`, so every run header logs them | Time-to-failure triggers then follow the delayed readings, so a delay can't leak through a wake-up | A separate info config outside the logged header |
| D043 | 2026-11-07 | `confirm_report`: only for a report already delivered to that role (`unknown_report`), at most 4 per run across all roles (`confirm_limit`). The reply comes 8 ticks later, to that role only, and describes the truth at reply time; numeric claims hold within 10%; a repair ETA's truth is the crew minutes still needed. The info layer's state isn't in the state hash; replay still checks it through observation digests | Rejections never reveal whether an unseen report exists; info-layer state is a pure function of scenario and actions | Truth at request time; per-role limits |
| D044 | 2026-11-07 | Known limitation: the early stop (D021/D031) waits for every pending event, hidden ones included, so a run with a future hidden block keeps going after an otherwise identical run would have stopped. The no-leak test compares the shared prefix in that case | Stopping without regard to pending events would skip future failures and change outcomes. The hint is weak: real scenarios rarely look stable while events are pending | Stopping on observable stability alone |
| D045 | 2026-11-07 | `BeliefState` keeps every estimate with value, as-of tick, source and integer confidence (verified 98, field 85, unverified 50, telemetry and confirm replies 100). The later tick wins; a tie goes to the more reliable source. Telemetry blocks are dated by first discovery, so a later "cleared" report can override them. A contestant that keeps a `belief` gets its digest written to every `dp` record | One simple, deterministic merge rule that rewards fresh information and works with delayed telemetry | Probabilistic beliefs (floats, and nothing yet needs them) |
| D046 | 2026-11-07 | The dependency graph is a NetworkX `DiGraph` rebuilt from belief at each decision point ("u depends on v"). The critical path picks the truck, depot and route that get fuel into the tank soonest on roads believed open (routing reuses the tie-breaking Dijkstra of D014); a loading truck counts as loaded, a truck unloading elsewhere as empty, and a truck already delivering keeps its route if it avoids believed blocks. `cascade_check` trips every overloaded substation in waves until nothing is overloaded | Deterministic, explainable answers for baselines and agents; NetworkX only holds structure and answers reachability | Solver-grade plans (that's M7) |
