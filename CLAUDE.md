# Blackout — working agreement

Research sandbox: Claude agents vs a rules script vs OR-Tools in a simulated city blackout. Not emergency software.

- Source of truth: docs/PRD.md. Build milestone by milestone (§12). Don't start a milestone before its dependencies are done; update the status table in §12 when one completes.
- Python 3.12 + uv. Checks: `uv run pytest`, `uv run ruff check .`, `uv run pyright`.
- Determinism: no randomness in the engine (seeded RNG only in the scenario generator); blake2b seeds, never `hash()`; integer units; sorted iteration; no wall clock in the sim or solver; Windows spawn guard (`if __name__ == "__main__":`) on entry points.
- Contestants never read ground truth (except the reference contestant). Wake triggers come from observations.
- Never open, edit or tune against `data/phrasing/test/` or `scenarios/test/`. The test bank is human-written.
- LLM code: official `anthropic` SDK; read the claude-api skill's Python docs before writing it; no network calls in tests (recorded fixtures); every batch goes through the budget guard.
- Log decisions in docs/DECISIONS.md.
- Golden run hashes in tests/test_demo.py change only when physics changes on purpose: update them, and say why in docs/DECISIONS.md.
- Handy: `uv run blackout run -s hello_blackout -c scripted --render ascii` (or `-s cascade`) shows a demo and logs it to runs/adhoc; `uv run blackout replay <run dir>` verifies a log; `uv run blackout score runs/adhoc` scores every logged run; `HYPOTHESIS_PROFILE=thorough uv run pytest tests/test_properties.py tests/test_replay.py` runs a deep property check; `uv run blackout run -s trap_assignment -c solver` (or `-c rules`, or `-s trap_depot`) shows where planning beats greedy dispatch; the solver's library contract is `blackout.controllers.solver.solve_plan` (docs/DECISIONS.md D061); `uv run blackout verify --suite dev` re-runs the frozen M8 dev suite and checks it's valid on this OS, and `uv run blackout gen --suite dev --check` regenerates it byte for byte (Windows only: CP-SAT is deterministic per OS, not across OSes, D084) (dev-v0 is frozen from M5 and can't be regenerated, D071); `uv run blackout batch --matrix configs/matrices/dev_baselines.yaml` runs the four baselines over dev (Rules vs Solver vs Reference by template, level and tier in results/dev_baselines/results.md); `uv run blackout prereg-hashes` prints the block the test guard checks in docs/PREREGISTRATION.md (M12). Scenario calibration uses do-nothing, Rules and the reference only, never the Solver (D072). `uv run blackout export-viewer <experiment> --select configs/viewer/preview.yaml` re-simulates selected runs into `viewer/public/data` (never the test suite, D086); `cd viewer && npm run dev` plays them (`npm run lint`, `npm test`, `npm run build` are the viewer's checks); the export format lives in `logs/export_viewer.py` and `viewer/src/types.ts`, change both and bump `VIEWER_DATA_VERSION`.
- LLM (M10): `uv run blackout run -s dev_t01_s0_l3 -c llm-parser` runs C4 from the synthetic fixtures in `tests/fixtures/llm_recordings` (no API call; `uv run blackout batch --matrix configs/matrices/m10_c4_fixtures.yaml` does it as a batch). `--llm live` is refused until the test bank is locked and committed (D093); the key comes only from `ANTHROPIC_API_KEY` or `.env`. After changing the parser prompt (`controllers/agents/prompts/parser_system.md`), its schema or `HARNESS_VERSION`, regenerate the fixtures with `uv run python -m tests.llm_fixtures`. Models, effort and the dated prices are in `configs/models.yaml`, caps in `configs/budget.yaml`; `uv run blackout budget` shows `runs/ledger.json`.
- Agents (M11): `uv run blackout run -s dev_t01_s0_l3 -c llm-single` (or `-c llm-single-solver`) runs C5/C6 from the synthetic fixtures in `tests/fixtures/llm_recordings/c5_synthetic` and `c6_synthetic` (C6's only match on Windows, D084); `uv run blackout batch --matrix configs/matrices/m11_single_fixtures.yaml` does it as a batch. The harness is `controllers/agents/` (harness, tools, render, prompts); after changing a prompt file, the tools, the rendering or `AGENT_HARNESS_VERSION`, regenerate the fixtures (`uv run python -m tests.llm_fixtures`, on Windows) and add a row to docs/PROMPTS.md.
- Run logs must stay deterministic (docs/DECISIONS.md D033): never put wall-clock time or machine details in run.jsonl.gz, only in summary.json.
